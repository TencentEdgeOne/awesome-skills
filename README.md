# Frontend Design · 界面设计交付

一个面向中文 Web 界面的 AI Skill，把简短需求变成有明确视觉方向、可复用设计令牌和可运行前端代码的完整交付。

不只是让页面「好看一点」，而是围绕主题、受众和页面目标，做出有理由的配色、字体与版式选择，减少千篇一律的 AI 模板感。

## 适用场景

- **落地页与品牌展示**：建立视觉记忆点，让首屏内容服务于产品或品牌主题。
- **仪表盘与管理后台**：组织信息层级、控制内容密度、完善界面状态。
- **组件库与多页面项目**：统一颜色、字体、间距、交互状态及主题规则。
- **高保真原型**：先比较设计方向，再落地为浏览器中可运行的页面。
- **已有界面优化**：尊重现有设计语言，针对排版、文案、视觉一致性与可访问性做改进。

## 核心能力

| 能力 | 具体做什么 | 交付内容 |
|---|---|---|
| 需求解析与方向提案 | 拆解主题、受众、首要目标和硬约束，提出 2–3 个真正不同的设计方向 | 方向卡、版式概念与线框 |
| 设计令牌与设计系统 | 统一颜色、字体、字阶、间距、圆角、动效及交互状态；通过令牌覆盖组织暗色主题 | `design-tokens.json`、CSS 变量或 Tailwind 配置 |
| 反模板化设计 | 检查视觉选择是否来自当前主题，避免机械套用卡片、渐变、装饰标签和入场动画 | 差异化方案与自查结论 |
| 中文排版与文案 | 制定中文字体与 fallback 策略，考虑字体子集化、中英混排、行高、行长和操作文案 | 字体策略、信息架构与界面文案 |
| 前端实现与质量走查 | 实现页面，并检查对比度、窄屏布局、键盘焦点、动效降级和加载稳定性 | 可运行代码与走查结果 |
| 可选发布预览 | 在你明确同意后，衔接 EdgeOne Makers 的部署能力 | 可访问的线上预览链接 |

### 设计不是换一套配色

这个 Skill 会先给出方向，而不是直接生成一套默认页面。每个方向包含立场、关键词、气质参照和一个值得尝试的视觉选择。确定方向后，再统一令牌、实现代码并复核效果。

它不禁止某种风格：如果你明确要求玻璃拟态、极简或特定配色，就按要求设计；重点是让每个选择有依据，而不是不管什么主题都套同一套模板。

### 中文界面有自己的设计要求

- 字体选择兼顾页面气质、中文覆盖与加载成本，提供完整 fallback 链。
- 正文行高建议为 1.7–1.9，行长控制在约 25–40 个汉字，并按实际字体与场景调整。
- 不给中文机械添加字距，不用无意义的英文标签装饰内容。
- 按钮说明动作，例如「保存修改」；加载态、空状态、错误态与成功态都有明确反馈。

## 安装与使用

在支持 `npx skills` 的环境中安装：

```bash
npx skills add vincentism/frontend-design
```

技能标识为 `distinctive-ui-design-zh`。完整行为说明见 [SKILL.md](SKILL.md)。安装后，在支持 Skill 的 AI 编程工具中直接描述你的界面需求。

### 示例需求

**新建页面**

> 为一家独立咖啡店做中文首页，主要面向附近居民，首要目标是让人查看菜单并到店。先给我三个不同的视觉方向，不要直接写代码。

**优化已有界面**

> 这个后台看起来太像通用模板。保留现有组件和品牌色，改善信息层级、中文排版和空状态，不要推倒重做。

**建立设计系统**

> 为这个多页面项目整理一套设计令牌，覆盖颜色、字体、间距和交互状态，支持暗色主题，并生成 CSS 变量。

需求中尽量说明：**做什么页面、给谁使用、最重要的动作、必须保留的约束**。不确定视觉风格也没关系，可以先比较方向卡再决定。

## 工作流程与交付

1. **理解需求**：明确主题、受众、页面目标和约束；缺失信息先提出具体建议并确认。
2. **比较方向**：展示 2–3 张方向卡、版式概念与线框，由你选择。
3. **建立令牌并自查**：统一视觉规则，检查方案是否只是通用默认答案。
4. **实现与复核**：输出可运行前端代码，逐项检查界面质量；环境支持时结合截图复查。
5. **按需发布**：仅在你明确同意后进入预览发布流程。

一次完整交付包括：**方向说明、设计令牌表、可运行代码、自查结论、质量走查结果**。线上预览是可选项，不是必需步骤。

## 随包工具

两个脚本均使用 Node.js 内置模块，无第三方依赖。在已安装 Skill 的目录或本仓库根目录运行。

### 设计令牌转 CSS

将准备好的 `design-tokens.json` 转为 CSS 自定义属性，可打印结果或写入文件：

```bash
node scripts/tokens-to-css.mjs design-tokens.json
node scripts/tokens-to-css.mjs design-tokens.json --out tokens.css
```

支持嵌套令牌；顶层 `dark` 对象会生成 `prefers-color-scheme: dark` 覆盖块。脚本只负责转换已有令牌，不会自动生成设计方案。

### 颜色对比度检查

输入前景色与背景色，输出 WCAG 对比度及 AA / AAA 判定：

```bash
node scripts/contrast.mjs '#1A1A1A' '#F7F5F0'
```

支持 `#RGB` 和 `#RRGGBB`。正文 AA 对比度要求至少 4.5:1，大字与 UI 组件至少 3:1。该脚本检查指定颜色组合，不替代整页可访问性走查。

## 能力边界

- 面向浏览器中运行的 Web 页面，不覆盖 iOS 或其他原生应用。
- 不替代框架选型、状态管理和业务逻辑开发，不主动修改项目配置。
- 截图复核、性能检查和线上预览取决于宿主环境可用的工具，不是本仓库自带的自动化服务。
- 预览发布由 `edgeone-makers-tools` 承接；安装与部署均需你明确同意，不会默认执行。
